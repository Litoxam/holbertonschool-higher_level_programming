# JWT Authentication

This document explains how **JSON Web Tokens (JWT)** are used to authenticate users after a successful login.

Unlike Basic Authentication, users no longer send their username and password with every request.

Instead, they authenticate once and receive a token that proves their identity.

---

# What is a JWT?

JWT stands for **JSON Web Token**.

A JWT is a digitally signed token generated by the server after a successful authentication.

Instead of repeatedly sending credentials, the client sends this token with future requests.

Example:

```text
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

The server verifies the token before granting access to protected resources.

---

# Why Use JWT?

With Basic Authentication:

```text
Request 1
↓

Username
Password

↓

Request 2
↓

Username
Password

↓

Request 3
↓

Username
Password
```

The credentials are transmitted every time.

With JWT:

```text
Login

↓

Username
Password

↓

JWT Token

↓

Request 2

↓

Bearer Token

↓

Request 3

↓

Bearer Token
```

The password is only sent once.

---

# Configuring JWT

Before generating tokens, Flask must initialize the JWT extension.

```python
app.config["JWT_SECRET_KEY"] = "your_secret_key"

jwt = JWTManager(app)
```

The secret key is used to:

* sign JWT tokens;
* verify JWT signatures.

If someone modifies the token, its signature becomes invalid and the request is rejected.

---

# The Login Endpoint

Users authenticate through the `/login` endpoint.

```python
@app.route("/login", methods=["POST"])
def post_login():
```

This endpoint expects a JSON request.

Example:

```json
{
    "username": "user1",
    "password": "password"
}
```

---

# Step 1 — Read the JSON Body

```python
data = request.get_json()
```

The request body is converted into a Python dictionary.

Result:

```python
{
    "username": "user1",
    "password": "password"
}
```

---

# Step 2 — Retrieve the Credentials

```python
username = data.get("username")
password = data.get("password")
```

Using `.get()` avoids raising an exception if a key is missing.

For example:

```python
data = {}
```

Then:

```python
data.get("username")
```

returns:

```python
None
```

instead of generating an error.

---

# Step 3 — Find the User

```python
user = users.get(username)
```

The application searches for the user inside the in-memory dictionary.

If the user exists:

```python
{
    "username": "user1",
    "password": "...",
    "role": "user"
}
```

Otherwise:

```python
None
```

is returned.

---

# Step 4 — Verify the Password

```python
if not user or not check_password_hash(user["password"], password):
    return jsonify({"error": "Unauthorized"}), 401
```

Two conditions are verified.

First:

```python
not user
```

Checks whether the username exists.

Second:

```python
check_password_hash()
```

Verifies the entered password against the stored hash.

If either verification fails, the API immediately returns:

```http
401 Unauthorized
```

---

# Step 5 — Create the JWT

If authentication succeeds:

```python
access_token = create_access_token(identity=username)
```

Flask generates a signed JWT.

The identity stored inside the token is:

```text
user1
```

or

```text
admin1
```

depending on who logged in.

---

# Step 6 — Return the Token

The token is returned to the client.

```python
return jsonify({
    "access_token": access_token
})
```

Example response:

```json
{
    "access_token": "eyJhbGciOiJIUzI1NiIs..."
}
```

The client must store this token for future requests.

---

# Using the JWT

Protected routes require the token inside the HTTP `Authorization` header.

Example:

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

The keyword **Bearer** tells the server that the following value is a JWT.

---

# Protecting an Endpoint

A route becomes protected by adding:

```python
@jwt_required()
```

Example:

```python
@app.route("/jwt-protected", methods=["GET"])
@jwt_required()
def get_jwt_protected():
    return "JWT Auth: Access Granted"
```

Before the function executes, Flask automatically verifies:

* that a token exists;
* that the token is correctly signed;
* that it has not expired;
* that it has not been modified.

If one of these checks fails, access is denied.

---

# Getting the Current User

Once the token has been validated, the stored identity can be retrieved.

```python
current_user = get_jwt_identity()
```

If the token was created with:

```python
create_access_token(identity="user1")
```

then:

```python
current_user
```

contains:

```text
user1
```

This identity is later used to determine the user's role.

---

# JWT Authentication Flow

```text
Client

POST /login

↓

Username
Password

↓

Verify Credentials

↓

Generate JWT

↓

Return Token

↓

Store Token

↓

GET /jwt-protected

↓

Authorization: Bearer TOKEN

↓

@jwt_required()

↓

Token Valid?

↓

Yes

↓

Execute Route
```

# Testing the Login Endpoint

## Valid Credentials

```bash
curl -X POST http://127.0.0.1:5000/login \
-H "Content-Type: application/json" \
-d '{
    "username":"user1",
    "password":"password"
}'
```

Response:

```json
{
    "access_token":"eyJhbGc..."
}
```

---

## Invalid Credentials

```bash
curl -X POST http://127.0.0.1:5000/login \
-H "Content-Type: application/json" \
-d '{
    "username":"user1",
    "password":"wrongpassword"
}'
```

Response:

```json
{
    "error":"Unauthorized"
}
```

Status:

```text
401 Unauthorized
```

# Testing a Protected Route

After obtaining a token:

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:5000/login \
-H "Content-Type: application/json" \
-d '{"username":"user1","password":"password"}' | jq -r .access_token)
```

Use it:

```bash
curl http://127.0.0.1:5000/jwt-protected \
-H "Authorization: Bearer $TOKEN"
```

Response:

```text
JWT Auth: Access Granted
```

---

## Missing Token

```bash
curl http://127.0.0.1:5000/jwt-protected
```

Response:

```text
401 Unauthorized
```

---

## Invalid Token

```bash
curl http://127.0.0.1:5000/jwt-protected \
-H "Authorization: Bearer invalid_token"
```

Response:

```text
401 Unauthorized
```

# Advantages of JWT

Compared to Basic Authentication, JWT offers several benefits:

* The password is only transmitted once.
* The client authenticates using a token.
* Tokens can contain user information.
* JWT is widely used by modern REST APIs.
* Authentication becomes stateless because the server does not need to store user sessions.

---

# Summary

JWT authentication introduced several new concepts:

* JSON Web Tokens
* Bearer Authentication
* JWT signatures
* Secret keys
* Protected routes
* User identity
* Stateless authentication
